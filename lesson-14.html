HTML, CSS и изображения

Каскад и специфичность CSS

Когда несколько CSS-правил задают одно свойство элементу, браузер применяет каскад. Специфичность — один из этапов выбора, а не единственное правило. Сначала важны origin, importance и layers; затем среди подходящих правил сравнивается точность селектора.

Как это работает — по шагам

  1. Удобно записывать специфичность тремя отдельными числами: ID, class/attribute/pseudo-class, element/pseudo-element. Это не десятичное число со свободным переносом разрядов.
  2. Сравнение идёт слева направо. Один ID может перевесить много class-селекторов в соответствующей ступени каскада.
  3. :where даёт нулевую специфичность. :is, :not и :has учитывают наиболее специфичный аргумент, поэтому наличие ID внутри может существенно изменить результат.
  4. При равенстве остальных условий побеждает более позднее правило. !important изменяет место декларации в каскаде, а не добавляет условную тысячу к счёту селектора.

Разберём на примере

У #app .item специфичность 1–1–0, у .panel .item:hover — 0–3–0, у :where(#app) .item — 0–1–0. Первое правило сильнее по ID, если сравниваем правила внутри одинаковых условий каскада. Сам #app внутри :where не добавляет веса.

Термины и элементы темы
ID / class / type
Три столбца специфичности: ID; classes/attributes/pseudo-classes; elements/pseudo-elements. Сравнение лексикографическое, не сумма десятичных очков.
:where / :is / :not / :has
:where имеет нулевую специфичность; у остальных учитывается наиболее специфичный аргумент, а не дополнительная «цена» самой функции.
Равенство
При прочих равных побеждает более позднее правило; !important — ступень каскада, а не «самая большая специфичность».

Коротко для собеседования

Сначала каскад, затем лексикографическое сравнение специфичности, затем порядок при равенстве. Не превращай всё объяснение в миф «больше классов всегда победит».

Подходы к стилям и дизайн-система

CSS-подход выбирают по тому, как команда организует стили, изоляцию, темы и доставку. Важно отделять язык стилей от способа подключения и runtime-поведения. Препроцессор превращает свой синтаксис в CSS; CSS Modules меняет область имён; CSS-in-JS может иметь разные модели генерации.

Как это работает — по шагам

  1. Обычный CSS использует глобальный каскад. Договорённости вроде BEM помогают управлять именами и связями, но изоляция поддерживается дисциплиной проекта.
  2. CSS Modules обычно локализует class names на этапе сборки. Правила всё ещё остаются CSS и подчиняются каскаду; это не отдельный движок layout.
  3. CSS-in-JS держит стили рядом с компонентом и может поддерживать динамику. Runtime-варианты добавляют работу при исполнении; compile-time варианты имеют другую цену и ограничения.
  4. Дизайн-система шире технического способа стилей: она включает tokens, состояния компонентов, accessibility и правила использования. UI-kit реализует лишь часть договорённостей.

Разберём на примере

SSR-приложению нужно показать правильные стили уже с первым HTML. Runtime CSS-in-JS требует корректного сбора/порядка стилей и hydration. CSS Modules может упростить этот участок, но динамические темы всё равно нужно продумать. Выбор зависит от условий, а не от лозунга «все стили рядом».

Термины и элементы темы
Обычный CSS / BEM
Небольшой runtime overhead; дисциплина имён и границы модулей поддерживаются договорённостями.
CSS Modules
Локальные имена classes на этапе сборки; значения по-прежнему подчиняются каскаду.
CSS-in-JS
Стили рядом с компонентом; runtime и compile-time реализации имеют разные затраты и SSR-требования.
Sass / Less / Stylus
Препроцессоры преобразуют расширенный синтаксис в CSS; Sass не SaaS.
Дизайн-система
Компоненты, tokens, accessibility и правила использования. UI-библиотека вроде Carbon реализует часть системы, но не заменяет продуктовые решения.

Коротко для собеседования

Сравнивай изоляцию, динамику, SSR, цену выполнения и сопровождение. Sass — препроцессор CSS; SaaS — модель предоставления ПО, это другое слово.

Загрузка скриптов: classic, async, defer, module

Браузер разбирает HTML по мере получения. Внешний JavaScript может одновременно требовать загрузки и выполнения. Атрибуты script определяют, какие из этих действий блокируют парсинг и сохраняется ли порядок между несколькими скриптами. Это влияет на доступность DOM и скорость первого отображения.

Как это работает — по шагам

  1. Обычный parser-inserted classic script без атрибутов останавливает parsing, пока ресурс не загрузится и код не выполнится.
  2. async позволяет загружать параллельно. Как только скрипт готов, он исполняется; два async-скрипта не обязаны сохранить порядок документа.
  3. defer для внешнего classic script загружает параллельно, а выполняет после parsing в порядке документа, до DOMContentLoaded.
  4. Module scripts по умолчанию ведут себя defer-подобно и загружают граф зависимостей. Отдельный async меняет правила момента исполнения.

Разберём на примере

library.js должен выполниться до app.js, который использует библиотеку. Два независимых async не гарантируют этого: маленький app может прийти раньше. Для classic-скриптов с такой зависимостью defer сохраняет порядок. Независимой аналитике может подойти async, если она не требует готового DOM.

Термины и элементы темы
Classic без атрибутов
Внешний script блокирует HTML parsing на загрузку и выполнение.
async
Загрузка параллельна parsing; исполнение — как только готов, порядок между скриптами не гарантирован.
defer
Для внешнего classic script: загрузка параллельно, исполнение после parsing в порядке документа, до DOMContentLoaded.
type=module
По умолчанию имеет defer-подобное поведение, использует module graph; async меняет момент исполнения. defer для module не нужен.

Коротко для собеседования

Разделяй загрузку и выполнение. async выбирает готовность, defer сохраняет порядок после parsing; module имеет собственную модель графа импортов.

Оптимизация изображений

Большая картинка может замедлить страницу даже при очень быстром JavaScript. Браузеру нужно найти ресурс, скачать подходящий вариант, декодировать его и выделить место. Поэтому оптимизация изображения включает не только сжатие, но и размер, момент загрузки и стабильность layout.

Как это работает — по шагам

  1. Выбери размер ресурса под реальное отображение и плотность экрана. Маленькой карточке не всегда нужен исходник шириной 5000 px.
  2. srcset и sizes помогают браузеру выбрать подходящий размер; picture позволяет выбрать формат или композицию под условия. Это отличается от простого CSS width:100%.
  3. width/height или aspect-ratio резервируют место до загрузки. Иначе браузер может сначала разложить текст, а потом сдвинуть его изображением.
  4. Lazy loading полезен для изображений вне экрана. Главное изображение первого экрана нужно обнаружить рано; его искусственное ожидание может ухудшить LCP.

Разберём на примере

На телефоне карточка занимает 180 CSS px, но загружается desktop-фото на несколько мегабайт. Responsive variants уменьшают передачу. Указанные размеры сохраняют место, пока файл идёт по сети. Для нижних карточек можно использовать lazy, а для главного hero-фото — приоритетную раннюю загрузку.

Термины и элементы темы
Формат и сжатие
AVIF/WebP часто полезны для raster; JPEG для фото и PNG для некоторых lossless-задач остаются вариантами. SVG — для подходящей векторной графики.
Responsive
srcset + sizes выбирают размер; picture выбирает формат или art direction. Не отправлять огромный desktop asset на маленький экран.
Стабильность
width/height или aspect-ratio резервируют место и уменьшают CLS.
Приоритет
loading=lazy для внеэкранных изображений; LCP обычно eager и при необходимости fetchpriority=high. alt описывает смысл, декоративным изображениям — пустой alt.

Коротко для собеседования

Правильное изображение — нужный формат, разумный размер, своевременная загрузка и заранее понятная геометрия. CSS-масштабирование само не уменьшает скачанный файл.

SVG: сильные стороны и ограничения

SVG описывает фигуры, линии, текст и их отношения, а не фиксированную сетку пикселей. Поэтому простой логотип может оставаться чётким при увеличении. Но векторное описание тоже имеет стоимость: сложная карта из тысяч элементов может требовать много памяти и вычислений.

Как это работает — по шагам

  1. Для геометрической графики SVG хранит инструкции формы. Браузер отображает их под нужный размер, что удобно для иконок, схем и логотипов.
  2. Inline SVG является частью DOM. Его элементы можно выбирать стилями, но вместе с этим растёт дерево и появляется поверхность для небезопасного недоверенного содержимого.
  3. SVG через img ведёт себя как изображение: нужен alt, а CSS страницы не управляет произвольными внутренними paths так же, как у inline.
  4. Для фото raster обычно естественнее. Размер файлов нужно сравнивать на реальных данных: «вектор всегда легче» неверно.

Разберём на примере

Простой значок корзины хорошо подходит для SVG: несколько paths масштабируются и могут менять цвет при inline-вставке. Фотография товара содержит множество деталей и не становится эффективнее только от помещения в SVG. Интерактивная карта требует отдельного анализа числа элементов и частоты обновления.

Термины и элементы темы
Преимущества
Масштабирование без потери чёткости, редактируемый текстовый формат, CSS/анимации при подходящем способе встраивания.
Стоимость
Сложный path/большое DOM-дерево могут быть тяжелее raster. SVG не гарантированно меньше PNG.
Безопасность и доступность
Недоверенный inline SVG требует sanitization. Для img важен alt, для inline — подходящее accessible name; внешнее img не даёт CSS-доступ ко внутренним paths.

Коротко для собеседования

SVG выгоден для подходящей векторной графики. Способ встраивания влияет на стили, доступность и безопасность; сложность содержимого влияет на производительность.

i18n и l10n

Перевести строки — только часть поддержки разных языков. Длина текста, формы множественного числа, формат даты, валюта и направление письма тоже меняются. i18n означает подготовку приложения к таким различиям, а l10n — конкретную адаптацию под выбранный язык и регион.

Как это работает — по шагам

  1. Вынеси сообщения из произвольной склейки строк. Переводчику нужна целая фраза с параметрами, потому что порядок слов может измениться.
  2. Количество требует plural rules. Для русского 1 товар, 2 товара и 5 товаров — не одна строка с механически добавленным окончанием.
  3. Даты и числа форматируются по locale, например через Intl. Timezone задаёт другую ось: один язык не определяет, в каком часовом поясе пользователь.
  4. Вёрстка должна выдерживать более длинный текст и при необходимости RTL. Не следует считать ширину английской кнопки универсальным контрактом.

Разберём на примере

Фраза "You have " + count + " messages" плохо переносится на языки с другими формами и порядком слов. Шаблон сообщения с plural-ветками сохраняет смысл целиком. Цена также требует locale-форматирования числа и явной валюты, а не только замены символа $.

Термины и элементы темы
i18n
Вынести сообщения, поддержать plurals/interpolation, форматирование чисел/дат и направление письма.
l10n
Перевод, выбор формулировок, региональных форматов и культурных особенностей.
Практические границы
Intl форматирует даты и числа; locale не равен timezone. Избегать склеивания фраз и предположения об одинаковой длине текста.

Коротко для собеседования

i18n — возможность корректно локализовать приложение; l10n — выполненная адаптация. Сообщения, plural rules, форматы и layout нужно рассматривать вместе.
