Объекты и память

Map и Set

Map и Set нужны для разных моделей данных. Map отвечает на вопрос «какое значение связано с этим ключом?». Set отвечает «встречалось ли это значение?». Порядок добавления сохраняется при обходе, но это не превращает Set в массив с адресацией по номеру.

Как это работает — по шагам

  1. В Map задаётся пара: users.set(id, user). Затем users.get(id) возвращает связанное значение. Ключи не обязаны быть строками: ими могут быть и сами объекты.
  2. В Set добавляется само значение: selectedIds.add(id). Повторное добавление того же значения не увеличивает число элементов.
  3. Для объектов сравнивается идентичность ссылки. Два объекта с одинаковыми полями считаются разными элементами, если созданы отдельно.
  4. Если действительно нужна позиция в Set, можно явно получить массив или пройти итератор. Это дополнительная работа; API Set не даёт get(2).

Разберём на примере

Map удобен для получения пользователя по ID. Set — для выбранных ID без повторов. Если добавить {id:1} дважды как два новых объекта, в Set будут два элемента. Если дважды добавить одну переменную, содержащую тот же объект, останется один.

const chosen = new Set(["a", "b", "a"]);
console.log(chosen.size); // 2
console.log(chosen.has("b")); // true
console.log([...chosen][1]); // "b" — индекс уже у нового массива
  1. Второе "a" не добавляет нового уникального значения.
  2. has проверяет наличие, а не позицию.
  3. Spread создаёт массив; именно массив затем позволяет обратиться по индексу.
Термины и элементы темы
Map
Ключом может быть любое значение. set/get/has/delete/clear, size; итерация keys/values/entries.
Set
add/has/delete/clear, size; нет доступа по числовому индексу и метода get(index). Для позиции можно явно создать массив.
Равенство
SameValueZero: NaN совпадает с NaN, +0 с -0. Два отдельно созданных объекта — разные значения.

Коротко по теме

Map — ключи и значения; Set — уникальные значения. У Set есть порядок обхода, но нет встроенных числовых индексов.

WeakMap и WeakSet

Обычная коллекция удерживает добавленные объекты, чтобы их можно было получить позже. Иногда это нежелательно: метаданные должны жить ровно столько, сколько живёт сам объект. WeakMap и WeakSet позволяют связывать данные с объектами, не делая коллекцию единственной причиной их сохранения в памяти.

Как это работает — по шагам

  1. В WeakMap ключом обычно служит объект, а значением — связанная информация. Например, описание DOM-узла или результат вычисления для объекта.
  2. Если объект больше не достижим из живого кода, наличие слабого ключа не должно само по себе удержать его. Сборщик может освободить соответствующую связь.
  3. WeakSet хранит только отметку о наличии объекта: например, «мы уже обходили этот узел». Он не хранит отдельное значение для ключа.
  4. Нельзя перечислить все ключи или узнать size: иначе результат наблюдал бы непредсказуемое время работы сборщика мусора. Для доступа нужно уже иметь сам ключ.

Разберём на примере

Ты помещаешь данные о карточке в обычный Map с ключом DOM-элементом. Даже после удаления элемента из документа Map может продолжать удерживать его. WeakMap удобен, когда метаданные не должны сохранять жизнь удалённому элементу при отсутствии других ссылок.

Термины и элементы темы
WeakMap
Слабые ключи: объекты и non-registered symbols. Значение доступно через живой ключ; get/set/has/delete.
WeakSet
Слабые значения тех же допустимых видов; add/has/delete. Для отметки «этот объект обработан».
Наблюдаемость
Нет size, перечисления элементов и clear: результат зависел бы от непредсказуемого GC. Сборка не обязана происходить сразу.

Коротко по теме

Слабая коллекция полезна для данных, привязанных к жизни объекта. Она не является перебираемым кэшем и не даёт команды «собери мусор прямо сейчас».

Сборка мусора и утечки

JavaScript обычно освобождает память автоматически, но не может понять, нужна ли она тебе по смыслу программы. Он анализирует достижимость: можно ли добраться до объекта из живой части приложения по цепочке ссылок. Если добраться можно, объект может оставаться в памяти даже тогда, когда пользователь уже закрыл соответствующий экран.

Как это работает — по шагам

  1. Начальная точка обхода — корни: например, глобальные объекты и активные вызовы. По их ссылкам находятся другие живые объекты.
  2. Достижимые объекты отмечаются. Недостижимые кандидаты могут быть освобождены; конкретное время и детали алгоритма выбирает движок.
  3. Два объекта могут ссылаться друг на друга. Если к этому циклу нет пути от корней, цикл не обязательно удерживается навсегда.
  4. Утечка часто означает, что приложение случайно сохраняет путь: listener замыкает большой объект, interval не остановлен, общий кэш растёт без ограничения.

Разберём на примере

Компонент добавил window listener. Его callback использует большой массив. Экран закрыли, но listener не сняли: window всё ещё удерживает callback, а callback — окружение с массивом. Очистка подписки разрывает этот путь, если других живых ссылок нет.

Термины и элементы темы
Mark-and-sweep
Отметить достижимые объекты и освободить недостижимые. Современные движки используют поколения и инкрементальные/параллельные варианты.
Циклы
Взаимные ссылки не мешают сборке, если весь цикл недостижим. Само число ссылок не определяет живость в этой модели.
Утечки
Неограниченный Map-кэш, забытый listener, interval или замыкание могут удерживать данные. Помогают cleanup, лимиты и heap snapshots.

Коротко по теме

GC ищет недостижимое, а не «давно не использованное». Для поиска утечки нужно искать удерживающие ссылки и разрывать ненужные связи.

Proxy и Reflect

Proxy позволяет поставить объект-посредник перед другим объектом. Когда код читает или изменяет свойство через посредника, можно перехватить операцию и добавить поведение: проверку, логирование или учёт зависимостей. Это работает именно с доступом через Proxy, а не магически со всеми ссылками на исходный объект.

Как это работает — по шагам

  1. Создаётся target — исходный объект — и handler с нужными ловушками. new Proxy(target, handler) возвращает отдельный объект для использования клиентским кодом.
  2. При чтении proxy.name вызывается get. При присваивании proxy.name = value — set. Другие операции, например in или delete, имеют свои ловушки.
  3. Внутри ловушки часто нужно выполнить обычное действие и только добавить проверку. Reflect помогает вызвать соответствующую стандартную операцию с нужным receiver.
  4. Вложенный объект остаётся обычным объектом, пока его отдельно не обернули. Нельзя также нарушать обязательные инварианты target: Proxy не отменяет правила языка.

Разберём на примере

Для свойства age можно отклонять отрицательное значение в set. Но если где-то осталась прямая ссылка target и код записал target.age = -1, этот доступ не проходит через Proxy. Это механизм организации доступа, а не изоляция от кода, имеющего target.

const target = { age: 20 };
const person = new Proxy(target, {
  set(obj, key, value, receiver) {
    if (key === "age" && value < 0) throw new Error("Возраст < 0");
    return Reflect.set(obj, key, value, receiver);
  }
});
person.age = 21;
  1. person отличается от target, хотя операции могут делегироваться target.
  2. Ловушка проверяет значение перед стандартной записью.
  3. Возвращённый boolean от Reflect.set сообщает результат записи; throw явно сообщает об ошибке.
Термины и элементы темы
get / set
Чтение и запись свойств можно логировать, валидировать или использовать для реактивности. set возвращает boolean успеха.
has / deleteProperty / ownKeys
Перехват in, delete и перечисления ключей; обязательны инварианты объекта, например для non-configurable свойств.
Reflect
Reflect.get/set помогают выполнить стандартную операцию с receiver. Вложенные объекты не становятся Proxy автоматически.

Коротко по теме

Proxy перехватывает операции с объектом-посредником. Он полезен для поведения вокруг доступа, но требует явной модели вложенности и соблюдения инвариантов.

Методы массивов

Методы массива легче запоминать по задаче и форме результата. Если каждому элементу соответствует новый результат, нужен map. Если нужно отобрать часть, filter. Если хочется получить одно итоговое значение, reduce. Отдельно всегда проверяй, меняется ли исходный массив: во frontend это влияет на state и сравнение ссылок.

Как это работает — по шагам

  1. Сначала сформулируй результат: новый массив, один элемент, индекс, boolean, строка или аккумулятор. Это сразу отсекает неподходящие методы.
  2. Затем выясни, разрешена ли мутация. sort и reverse работают на исходном массиве; toSorted и toReversed создают новый. Поверхностная копия не копирует вложенные объекты.
  3. Predicate — функция условия. find ищет первый элемент, для которого условие истинно; some проверяет, есть ли такой элемент вообще; every проверяет все.
  4. Callback может сам изменить внешний объект, даже если метод формально не мутирует исходный массив. Название «немутирующий метод» не гарантирует чистоту твоей функции.

Разберём на примере

Для экрана товаров filter выбирает доступные товары, map получает их названия, some проверяет наличие скидок. Если отсортировать props.products через sort, изменится переданный массив. Для независимого порядка отображения лучше использовать toSorted или явную копию с sort.

Термины и элементы темы
map
Новый массив результатов callback; не изменяет исходный массив сам по себе.
filter
Новый массив элементов, прошедших predicate.
reduce
Один аккумулятор, обход слева направо; initialValue особенно важен для пустого массива.
reduceRight
Свёртка справа налево.
flatMap
Преобразование с объединением на один уровень.
find
Первый подходящий элемент или undefined.
findIndex
Индекс первого подходящего элемента или -1.
includes
Наличие значения по SameValueZero; возвращает boolean.
indexOf / lastIndexOf
Первый / последний индекс значения по строгому равенству или -1; NaN таким способом не находится.
some / every
Хотя бы один / все удовлетворяют условию; для пустого массива false / true.
push / pop
Добавить в конец / убрать с конца; мутируют; возвращают новую длину / удалённый элемент.
shift / unshift
Убрать в начале / добавить в начало; мутируют; возвращают элемент / новую длину.
splice
Изменяет массив: удалить/вставить; возвращает удалённые элементы.
sort / reverse
Сортирует / переворачивает на месте. sort без comparator сравнивает строковые представления.
fill
Заполняет диапазон одним значением и мутирует массив; объект будет одной общей ссылкой.
slice / concat
Копия диапазона / объединение без мутации; копирование поверхностное.
join
Строка из элементов с разделителем.
toSorted / toReversed / toSpliced / with
Новые массивы без соответствующей мутации исходника; with заменяет значение по индексу.

Коротко по теме

Для преобразования беру map/filter/flatMap, для свёртки reduce, для поиска find/findIndex, для проверки some/every/includes. push, splice, sort и другие изменяющие методы требуют осторожности с React-state. slice/concat и новые toSorted/toReversed/toSpliced/with возвращают новый массив, но вложенные ссылки могут оставаться общими. Для каждого метода называю результат и мутацию.

Поверхностное и глубокое копирование

Переменная с объектом хранит ссылку. Поэтому «скопировать объект» может означать разные вещи: создать только новый внешний контейнер или создать новые вложенные данные тоже. Это особенно важно для React: новая ссылка сверху не мешает случайно изменить вложенный объект, который всё ещё общий со старым состоянием.

Как это работает — по шагам

  1. Spread создаёт новый верхний объект, но копирует значения его свойств. Если значением была ссылка на другой объект, ссылка остаётся той же.
  2. JSON.stringify/parse сначала превращает данные в JSON, затем создаёт новые данные из текста. Всё, что JSON не умеет выразить, теряется, меняется или вызывает ошибку.
  3. structuredClone поддерживает больше встроенных структур и циклы. Но он не является универсальным копировщиком поведения: функции и произвольные экземпляры со всей семантикой не переносятся как есть.
  4. Часто вместо копирования всего дерева достаточно создать новые объекты только вдоль изменяемого пути, оставив неизменённые части общими.

Разберём на примере

После copy = {...user} выражения copy.profile и user.profile всё ещё указывают на один объект. copy.profile.name = "Новое имя" изменит и исходные данные. Чтобы независимо поменять имя, нужно также создать новую profile, а затем присвоить её новой внешней копии.

const oldUser = { profile: { name: "Аня" } };
const nextUser = {
  ...oldUser,
  profile: { ...oldUser.profile, name: "Вера" }
};
// oldUser.profile.name по-прежнему "Аня"
  1. Внешний spread создаёт новый объект пользователя.
  2. Вложенный spread создаёт новую profile, поэтому её изменение не затрагивает oldUser.profile.
  3. Если бы у profile были вложенные объекты, они остались бы общими до отдельного копирования.
Термины и элементы темы
Spread / Object.assign
Поверхностная копия собственных enumerable свойств; вложенные объекты сохраняют ссылки.
JSON round trip
Только JSON-совместимые данные: Date станет строкой, функции/undefined теряются или меняют представление, BigInt и циклы обычно приводят к ошибке.
structuredClone
Поддерживает циклы, Date, Map, Set, ArrayBuffer; функции и DOM-узлы не клонирует, не сохраняет произвольные прототипы и descriptors.

Коротко по теме

Сначала уточни, какие уровни и типы нужно копировать. Поверхностная копия сохраняет вложенные ссылки; JSON — преобразование формата; structuredClone поддерживает определённый набор данных.

Замыкания, call/apply/bind

Замыкание появляется, когда функция использует переменную из окружающей области видимости. Эта возможность остаётся после завершения внешнего вызова. Важно представлять не коробку со снимком всех значений, а доступ к определённому лексическому окружению: разные вызовы фабрики могут создать разные окружения.

Как это работает — по шагам

  1. Внешняя функция создаёт переменную и возвращает внутреннюю функцию. Внутренняя продолжает иметь доступ к этой переменной.
  2. При следующих вызовах внутренней функции используется то же окружение. Поэтому изменение счётчика сохраняется между вызовами.
  3. Другой вызов внешней функции создаёт новый счётчик. Совпадение имён переменных не делает их одной общей переменной.
  4. call/apply/bind решают другой вопрос: какое значение this и какие аргументы получает вызов. Лексическое окружение функции и её this не следует смешивать.

Разберём на примере

Фабрика makeCounter возвращает функцию увеличения count. counterA() меняет count первого вызова фабрики; counterB() — другого. В React callback конкретного render также связан со своим окружением, поэтому старый callback может продолжать видеть state старого render.

function makeCounter() {
  let count = 0;
  return () => ++count;
}
const a = makeCounter();
const b = makeCounter();
a(); // 1
a(); // 2
b(); // 1
  1. Переменная count создаётся отдельно для каждого вызова makeCounter.
  2. Возвращённая функция продолжает обращаться к своему count после завершения makeCounter.
  3. Поэтому b не продолжает счёт a.
Термины и элементы темы
Замыкание
Счётчик, фабрика обработчика и приватное состояние — типичные примеры; удерживаемые переменные могут удерживать память.
call / apply
Сразу вызвать функцию с заданным this; call принимает аргументы отдельно, apply — array-like.
bind
Создать функцию с закреплённым this и/или первыми аргументами. Стрелочная функция использует лексический this.
Каррирование
Преобразовать f(a,b,c) в цепочку f(a)(b)(c). Отличается от частичного применения, где фиксируется часть аргументов.

Коротко по теме

Замыкание сохраняет доступ к окружению создания. call и apply вызывают функцию с заданным this; bind создаёт новую связанную функцию; каррирование разбивает получение аргументов на вызовы.
