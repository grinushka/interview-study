React: хуки и эффекты

Хуки: явный учебный набор

Хук — способ использовать возможности React внутри function component или другого хука. Лучше сначала связать названия с задачами: хранение state, чтение context, работа с DOM, синхронизация снаружи, оптимизация. Тогда список перестаёт быть набором похожих use-слов.

Как это работает — по шагам

  1. Для значения, влияющего на UI, обычно нужен useState или useReducer. Если значение меняется, но экран от него не зависит напрямую, может подойти useRef.
  2. Для context используется useContext. Для внешней системы — effect; для чтения геометрии перед paint — layout effect. Это разные причины использовать хук.
  3. useMemo и useCallback помогают избежать некоторых повторных вычислений и изменений ссылок. useTransition и useDeferredValue позволяют управлять срочностью, а не хранить другое значение вместо state.
  4. Обычные хуки вызываются в одинаковом порядке на верхнем уровне. Custom hook объединяет логику, но каждый вызов обычно имеет собственное состояние. API use имеет отдельные правила.

Разберём на примере

Поле формы хранит текст в useState. DOM-узел поля доступен через useRef. Подписка на внешнюю систему живёт в useEffect с cleanup. Дорогой производный список можно мемоизировать после измерений. Один компонент может использовать несколько хуков, потому что у него несколько независимых задач.

React: встроенные хуки

useEffect: внешние системы и cleanup

React умеет вычислять и обновлять свой UI, но за его пределами существуют соединения, timers, browser listeners и сторонние widgets. Их состояние нужно согласовывать с тем, что сейчас отображается. Эффект описывает такой процесс согласования, а не просто место для кода «после render».

Как это работает — по шагам

  1. Сначала определи внешнюю систему. Например, показ комнаты чата требует активного соединения именно с этой комнатой.
  2. Setup запускает синхронизацию: подключает комнату или подписывает listener. Зависимости описывают, при изменении чего старый процесс больше не подходит.
  3. Cleanup отменяет сделанное setup. Перед соединением с новой комнатой нужно отключить старую; при unmount — прекратить подписку совсем.
  4. Если значение вычисляется из props/state, внешней системы может не быть: его можно вычислить в render. Если действие вызвано кликом «Купить», подходящее место часто event handler.

Разберём на примере

Компонент ChatRoom получает roomId. При mount подключается к этой комнате. При смене roomId React сначала запускает cleanup прежнего эффекта, затем setup нового. В development StrictMode может дополнительно проверить эту симметрию повторным setup/cleanup.

Термины и элементы темы
Setup
Подписать listener, подключить канал, запустить таймер или синхронизировать imperative widget.
Cleanup
Снять подписку, остановить таймер, закрыть соединение. Перед новым setup со сменившимися зависимостями React выполняет прежний cleanup; также при unmount.
Что не требует эффекта
Вычисляемые данные можно получить в render, действие пользователя — в event handler. Не копировать props в state без необходимости.
Разработка
StrictMode может выполнить дополнительный цикл setup → cleanup → setup, чтобы выявить ошибки очистки.

Коротко для собеседования

useEffect синхронизирует UI с внешней системой. Хороший эффект имеет понятные setup, зависимости и cleanup, а не произвольный набор действий.

Массив зависимостей эффектов

Массив зависимостей не задаёт произвольное расписание. Он сообщает, какие реактивные значения использует процесс синхронизации. React сравнивает значения из нового render с предыдущими, чтобы решить, можно ли оставить старый эффект. Глубокого обхода объектов при этом нет.

Как это работает — по шагам

  1. Без массива React не получает условия пропуска: setup выполняется после каждого соответствующего commit, с cleanup прежнего эффекта перед новым setup.
  2. Пустой массив означает, что процесс не зависит от реактивных значений render. Он всё равно связан с mount/unmount, а в development возможен дополнительный проверочный цикл.
  3. Для [roomId] React сравнит прошлое и новое roomId через Object.is. Если значение изменилось, прежний процесс очищается и создаётся новый.
  4. Для [options] сравнивается ссылка. Изменение options.roomId при той же ссылке не считается новой зависимостью. Более того, мутация сама по себе не заставляет React выполнить render.

Разберём на примере

В примере object.address изменился, но object остался прежним. Даже если другой state вызвал render, [object] совпадает с предыдущим массивом по значениям. [object.address] позволил бы сравнить поле при новом render, но правильнее не строить state-логику на скрытых мутациях.

const options = { room: "a" };
// Представим effect с зависимостью [options].
options.room = "b";
// Ссылка прежняя: Object.is(options, options) === true.
// Новая ссылка:
const nextOptions = { ...options, room: "c" };
// Object.is(options, nextOptions) === false.
  1. Смена поля меняет содержимое объекта, но не его identity.
  2. React не получает автоматического уведомления от обычного присваивания object.field.
  3. Новый объект даёт другую ссылку; эффект сравнит её только при очередном render/commit компонента.
Термины и элементы темы
Без массива
Setup после каждого commit компонента, а перед следующим setup — cleanup предыдущего.
Пустой массив []
Нет реактивных зависимостей. Mount setup и unmount cleanup; дополнительный dev-цикл StrictMode и повторный mount возможны.
[a, b]
Перезапустить синхронизацию, когда хотя бы одно значение отличается по Object.is.
Объект с той же ссылкой
Изменение поля не меняет identity зависимости. Сама мутация не запускает render; даже при другом render эффект с [object] не перезапустится из-за этого поля.

Коротко для собеседования

Зависимости сравниваются по позициям через Object.is. Массив должен отражать читаемые реактивные значения, а не использоваться для подавления неудобного повторного запуска.

Уточнение к Notion: [] не означает «ровно один раз навсегда»; useLayoutEffect не делает глубокое сравнение зависимостей.

useEffect и useLayoutEffect

Некоторые действия должны закончиться до того, как пользователь увидит новый кадр. Например, tooltip сначала нужно измерить, чтобы выбрать положение. Большинство подписок и сетевой синхронизации не требуют задерживать отрисовку. Между этими случаями и выбирают useLayoutEffect или useEffect.

Как это работает — по шагам

  1. После изменения DOM layout effect может прочитать фактическую геометрию. Если он обновит state для коррекции позиции, React может применить коррекцию до repaint.
  2. Пока layout effect выполняет работу, отображение кадра ждёт. Дорогие вычисления в нём напрямую ухудшают отзывчивость.
  3. Обычный effect подходит для соединений, подписок и другой синхронизации, которой не нужно скрывать промежуточный визуальный результат.
  4. Не стоит заучивать «useEffect всегда после paint». Время связано с причиной обновления и поведением React; для предотвращения визуального мерцания есть специальная гарантия layout effect.

Разберём на примере

Tooltip впервые появился над кнопкой, но не помещается. Если измерить его только после показа и перенести вниз, пользователь заметит прыжок. Layout effect позволяет измерить готовый DOM и скорректировать позицию до видимого кадра. Для открытия WebSocket такого преимущества нет.

Термины и элементы темы
useLayoutEffect
Выполняется до repaint и может блокировать его. Подходит для измерения tooltip и синхронной коррекции позиции.
useEffect
Обычно не блокирует paint; для обновлений от взаимодействий может выполняться до paint. Нельзя обещать «всегда после paint».
Общее
Оба эффекта работают только на клиенте, требуют корректных зависимостей и cleanup. Избыточный layout effect ухудшает отзывчивость.

Коротко для собеседования

useLayoutEffect выбирают для нужной до paint работы с layout. Его цена — блокировка paint. Правила зависимостей и cleanup у двух эффектов одинаковы.
